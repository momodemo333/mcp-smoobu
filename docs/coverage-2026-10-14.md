## Removed from discovery (fail closed)
- create_guest and update_guest: no public POST/PUT guest contracts found in complete current documentation (only list/detail GET). Removed handlers; client endpoint allowlist also rejects these mutations.
- list_online_check_ins: /api/online-check-in not in public contract. Actual documented OCI GET/POST /api/oci/{reservationId}/partner/{partnerId} is partner-only. No speculative replacement.
- Removed fields in write schemas fail validation; do not silently translate legacy rates or booking-edit semantics.

## Limits and backlog
- No mark-read/no_reply_needed, inquiry/preapproval or Airbnb alteration handling. Updating Smoobu booking fields is NOT acceptance on Airbnb.
- No webhook changes, OCI partner access, guest CRUD, placeholder/translation CRUD, autonomous pricing or local status registry.
- No OAuth token lifecycle; HMAC preferred, legacy fallback retained (documented sunset 2026-10-31).
- Local per-client sliding quota cannot coordinate other processes/keys; server retry headers remain authoritative. Deadline 30s includes waiting, so long quota waits return TIMEOUT, not an early retry.
- At most two retries for GET and fixed availability POST (network failures, 429, 5xx); zero mutation retries. Retry-After seconds/date and X-RateLimit-Retry-After Unix timestamp honored; longer of both wins. Redirects refused; fresh nonce each attempt.
- Message extraction is best-effort plain text, not an HTML renderer/sanitizer. Script/style stripped, common/numeric entities decoded; unknown named entities may remain. Text defaults 4000 chars per message, explicit truncation metadata, raise maxContentChars to 100000. One page only; caller follows nextPage. No invented read-state flags.
- Rates preview is no pricing recommendation: no before/after snapshot or atomic transaction. Local caps (100 apartments, 100 operations, 366 date specs/operation, 365-day difference/range, 36600 apartment-days) are connector safety limits, not advertised Smoobu limits. Overlaps and duplicate IDs rejected. No automatic past-date policy or channel markup calculation.
- Strict response schema validation is not exhaustive; malformed successful envelopes may still fail at a handler. SDK emits tool errors; no false real-server compatibility claim.
- Price-element amount >=0 is a conservative connector restriction, not a documented API-wide restriction; negative discount encoding needs support confirmation before relaxing.
- Query search for guests and additional documented reservation/create priceElements are intentionally not exposed yet.
